# Memory keeps facts for at most two years, deletes them with their source, and logs every read

Buyers ask for a written retention policy, GDPR limits storage to what's needed, and Google's and Microsoft's terms require deleting data when it's deleted or revoked at the source. A fact goes when its source is deleted or loses access in the app (seen on the app's change events and nightly), when its connection is removed (invariant 3), or when no source has supported it for 24 months; superseded versions are kept as history within the same window, and admins can shorten it. We chose a fixed window over keeping facts until their source goes, which leaves "how long do you keep it" without an answer, and over 12 months, which loses yearly patterns such as annual renewals.

## Consequences

- **Forgetting a person.** An admin can forget a person by email address: their object, every fact about them and their embeddings are deleted, and the address goes on a do-not-learn list so new mail doesn't rebuild them. The admin sees only that it was done and how many facts went. This also serves erasure requests from people who never used Mycel.
- **Access log.** Every read of memory, by a person, a workflow, the agent or an MCP client, is logged: who, when and which object, never the content. Admins see their company's log; members see reads of facts from their own sources. Our staff read memory only with the customer's documented consent for a specific case, and that read is logged where the customer sees it.
- **Keys.** Memory relies on the database's encryption at rest: Neon encrypts storage and backups with AES-256 under keys in AWS KMS or Azure Key Vault, which meets Google's rule. Facts, embeddings and the keyword index have to be readable by the database to be searched, so they can't also be encrypted with a key per company. A key per company, held in a KMS, encrypts what is never searched: held sends (ADR-0019) and the do-not-learn list, which keeps a keyed hash of each address rather than the address. A company that leaves has its rows deleted and its key destroyed. A key per company for searchable memory waits until we move memory to storage that offers one per tenant.
- **Deletion promise:** gone from the live database at once (refresh tokens too, as Google requires); database backups and Inngest's run state age out within 30 days.
