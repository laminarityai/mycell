# Integrations: what each app lets a workflow do

Checked 2026-10-21 against primary sources: each vendor's API reference, guides, release notes and permission docs, and Nango's docs and `providers.yaml`. Each file cites its own sources, with page dates where shown, and marks what it couldn't confirm.

The question: what would Mycel's catalog need, app by app, so the builder chat can make any workflow a small company describes? And, since the goal is for the builder to create integrations itself, even for apps with no catalog actions yet, what would that take?

Every app is read through ADR-0013's four parts: what Mycel reads, what can start a run, what a workflow may do (each with a fixed risk level), and the **pending form**, the app's own way of holding an action until a person approves it.

## Decisions this raises

1. **The builder creating integrations itself** reverses invariant 5 and non-goal 4, and has to keep invariants 4 and 8 and ADR-0013. Nango's Functions API already lets an agent write, test and deploy an integration. But no signal a fixed rule can trust gives an arbitrary API call one of our five risk levels. Nobody else lets an AI create a lasting action whose risk it sets itself. [builder-made-integrations.md](builder-made-integrations.md) sets out four ways to keep invariant 4: a person catalogs what the builder drafts; request templates that fixed rules rank; builder-made actions on read-only connections only; or trusted vendors' MCP tools through a fixed table. Needs a grilling session and an ADR.
2. **What counts as "external".** `docs/intent.md` says nothing may **leave the company** without a person approving it. `docs/architecture.md` says anything that **reaches other people** waits. Gmail never forced a choice, but comments, assignments and notifications in monday, Asana, Notion, Slack and Teams reach coworkers without leaving the company.
3. **Apps with no pending form**: Slack, Google Chat, Teams, Drive and OneDrive sharing, Word, Excel, Zendesk replies, and comments everywhere. ADR-0013 says such an app waits until we design one. Most of the candidate designs hold the item somewhere private and move it on approval, or post a preview with approve buttons.
4. **App-store gates** come before selling to other companies: Slack and Zendesk in effect require a Marketplace listing, Shopify requires App Store review and its billing, and monday's API limits push toward its Marketplace. Microsoft needs each company's admin to approve Mycel once. Google's `gmail.modify` and `drive.readonly` need a yearly security assessment.
5. **Accounting under v1's ban on financial actions.** Creating a QuickBooks invoice or bill, and approving one in Xero, posts to the books, so it's `financial`. What's left is chasing overdue invoices through Gmail drafts, drafting estimates, quotes and Xero draft bills, and keeping contacts tidy. Xero's terms on AI use, and Intuit's ban on "data mining", need legal review before either is mined or sent to a model.
6. **Push triggers outside Nango.** Gmail's and Calendar's push, the Workspace Events API, monday's and Asana's webhooks, and Microsoft's subscriptions either aren't forwarded by Nango for the generic `google` integration Mycel uses, or need subscriptions Mycel creates and renews itself. Deleting a connection then has to delete those subscriptions too (invariant 3).

## Already acted on

- Docs reviews are approved or declined in Mycel (ADR-0016), and #67 and #71 say so.
- #67–#70 and #72 now match Google's docs: free-time lookup dropped (it needs a Calendar permission Mycel doesn't ask for); a waiting event is private and doesn't block time; Tasks leave tasks assigned from Docs or Chat alone; the invite trigger skips cancelled and Gmail-added events and records the invites it can't see.
