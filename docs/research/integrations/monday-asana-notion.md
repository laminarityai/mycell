# Work tracking and docs: monday.com, Asana, Notion

Researched 2026-10-21 from vendor docs, Nango's `providers.yaml` (last commit 2026-10-19) and Nango's provider pages. Page last-updated dates are given where the page shows one. Citations are numbered; see **Sources**.

## Points that apply to all three apps

- **Most actions stay inside the company.** Creating, editing, moving and commenting on work items reaches coworkers, not outsiders. The exception is **guests**. All three apps let a workspace add people from outside the company's domain (monday guests on shareable boards, Asana guests, Notion guests), and anything those guests can see, or are notified about, leaves the company. That covers assigning a task to a guest, commenting where a guest follows, or creating an item on a board shared with guests. So for one catalog action, the risk depends on where it runs.
  - **Proposal:** keep each catalog risk level fixed (invariant 4). Give the `internal_reversible` actions a deterministic guard in their adapters: before writing, check whether the target board, project or page has guest members or followers, or is published, and refuse if so. Separate `external_send` variants that use a pending form (below) can handle the guest case.
- **Mycel's docs disagree on what "external" means.** `docs/intent.md` non-goal 1 says "Nothing leaves the company without a human sending or approving it." `docs/architecture.md` says "Anything that reaches other people waits in its app's pending form." In these apps, almost every write notifies some coworker: a comment, an assignment, an @-mention, monday's `create_notification`. Under the intent.md reading these actions are `internal_reversible`. Under the architecture.md reading they are `external_send`, which would gate nearly everything. This research uses the intent.md reading: coworker notifications are `internal_reversible`, and they are flagged in the tables. **This needs a decision.**
- **A pending form by staging and moving.** None of the three apps has a "draft comment" or "draft item" state. Each does, though, have a cheap way to create something where outsiders can't see it, then move or reveal it on approval. This is the same pattern as Mycel's Calendar event created with no guests:
  - **Asana:** create the task with no guest assignee or followers. On approval, set the assignee or call `addFollowers`.
  - **monday:** create the item on a private staging board. On approval, call `move_item_to_board`.
  - **Notion:** create the page under a private "Mycel drafts" page. On approval, call **Move a page**.

  Comments and updates have no such state in any of the three apps.

- **As context for the builder.** Notion is company knowledge: SOPs, wikis, meeting notes. monday and Asana are company process: which boards and projects exist, their statuses and columns, who owns what. Discovery can mine the work-item streams for repetitive work, such as the same form intake every week or the same status change followed by the same comment.

## monday.com

### 1. Summary

A work-management board tool: items (rows) on boards, with typed columns (status, people, date, file and more), groups, subitems, updates (comments), forms, docs and automations. Small companies use it for client projects, request intake, sales pipelines (monday CRM), content calendars and HR onboarding. monday reported 250k+ paying customers (see `00-ranking.md`).

Top workflows:

1. **Intake:** an email or form becomes an item with filled columns and an owner.
2. **Status-change follow-up:** when Status becomes "Done", post an update, notify the owner, or create the next item.
3. **Stalled-item nudges:** items past due or unchanged for N days get a reminder notification and an update.
4. **Weekly digest:** a board summary goes into a Gmail draft to the client (the external send happens in Gmail).
5. **Triage:** classify new items and set priority, group and owner.

### 4. Triggers

- **Webhooks** [M2] (updated 2026-09-06):
  - Created per board with `create_webhook(board_id, url, event, config)`. There are no account-level or workspace-level webhooks, so Mycel must create one per (board, event).
  - Events (exact names): `change_column_value`, `change_status_column_value`, `change_subitem_column_value`, `change_specific_column_value`, `change_name`, `create_item`, `item_archived`, `item_deleted`, `item_moved_to_any_group`, `item_moved_to_specific_group`, `item_restored`, `create_subitem`, `change_subitem_name`, `move_subitem`, `subitem_archived`, `subitem_deleted`, `create_column`, `create_update`, `edit_update`, `delete_update`, `create_subitem_update`. `config` narrows some events, for example to a particular column.
  - **Verification:** a one-time `challenge` POST that Mycel must echo back. Webhooks created with an app's OAuth token carry a **JWT signed with the app's Signing Secret**, and end users can't disable them.
  - **Retries:** "once a minute for 30 minutes", then the event is lost. Latency isn't stated.
  - **Form submissions** arrive as `create_item` on the form's board.
- **Polling:** `activity_logs(from, to)` per board [M12]. `items_page` can filter on columns but has no "changed since" cursor, so `activity_logs` is the delta source.

### 5. Auth

- **Scopes** [M3] (updated 2026-07-07): `account:read`, `assets:read`, `boards:read`, `boards:write`, `departments:read/write`, `docs:read/write`, `me:read`, `notifications:write`, `tags:read`, `teams:read/write`, `updates:read/write`, `users:read/write`, `webhooks:read/write`, `workspaces:read/write`. Scopes are coarse: `boards:write` covers every item and column write, including deletes, so the catalog has to enforce narrower limits.
- **Account-level install.** "Account admins are the only users who can install apps." A non-admin clicks "Request to add", and the admins approve. On Enterprise, custom roles can be allowed to install [M16]. **So a member can't connect monday alone; an admin must install the Mycel app first.** The API then acts with the authorizing user's own board permissions.
- **OAuth 2.1 migration (2026).**
  - The new flow requires PKCE. Access tokens expire (examples show `expires_in: 3600`), and the token endpoint moved to `https://auth.monday.com/oauth_ms/oauth/token`. There is a revoke endpoint and a temporary `/oauth_ms/oauth/migrate` endpoint for legacy tokens [M4] (updated 2026-09-23).
  - The original announcement (2026-07-13) said legacy tokens "stop working" on 2026-10-01. A staff update on 2026-07-27 replaced the 6-month hard expiry with a rule that a **refresh token lapses after 3 months unused** [M17].
  - The cutoff for legacy tokens after that revision isn't clear from the sources, so treat legacy as gone.
- **Review:** a private (unlisted) app needs no review. Marketplace listing has its own review, which I didn't research. Listing matters for rate limits (see 6).

### 6. Limits

Source: [M1] (updated 2026-10-19).

- **Complexity budget:** app tokens get **5M points/minute for reads and 5M for writes**. A single query is capped at 5M. Budgets are **shared across apps on the account**. Errors: `COMPLEXITY_BUDGET_EXHAUSTED`, `REQUEST_MAX_COMPLEXITY_EXCEEDED`, each with `retry_in_seconds`. Add the `complexity` field to a query to see its cost.
- **Per minute:** 1,000 queries (most plans), 2,500 (Pro), 5,000 (Enterprise).
- **Concurrency:** 40 / 100 / 250 requests (other plans / Pro / Enterprise).
- **IP limit:** 5,000 requests per 10 s.
- **Daily call limit, per account, reset at midnight UTC: 1,000 on Free, Standard and Basic; 10,000 on Pro; 25,000 on Enterprise.**
  - It counts calls through personal tokens, private apps and public apps, **"excluding marketplace apps and those developed by monday.com"**.
  - Calls through monday's hosted MCP server count too.
  - Rate-limited requests count 0.1 call; high-complexity queries count 1+ calls.
  - More quota can be bought as an API add-on.
- **What that means for Mycel:** most small companies are on Standard. An unlisted Mycel app would share 1,000 calls a day with every other non-marketplace integration on the account, which is too little for webhook-driven runs that each read and write a few times. **Listing on the monday marketplace removes the daily cap**, which makes listing close to a requirement.
- **API versions:** quarterly (`2026-04` Maintenance, `2026-07` Current, `2026-10` RC). Each is stable for at least 6 months, and a deprecated version routes to Maintenance [M18] (updated 2026-09-06). Pin the version in the header and plan a quarterly upgrade.

### 7. Nango

- Provider `monday` (OAuth2) uses `authorization_url: https://auth.monday.com/oauth2/authorize`, **`token_url: https://auth.monday.com/oauth2/token`**, `disable_pkce: true` and `force_install_if_needed: true`. The proxy base URL is `https://api.monday.com` [N1].
- **This is the legacy (pre-2.1) flow.** Nango's monday page still says "Access tokens do not expire... does not support refresh tokens" [N2]. Before building, confirm whether Nango supports monday's OAuth 2.1 (PKCE, `/oauth_ms/oauth/token`, refresh). Otherwise new connections may fail, or need a custom provider config.
- `monday-api-key` (API key) also exists. It breaks Mycel's OAuth-only rule.
- **No `webhook_routing_script`:** Nango doesn't receive or forward monday webhooks. Mycel needs its own route handler that answers the `challenge` and verifies the JWT. CLAUDE.md allows route handlers for webhooks.
- Nango publishes 40+ prebuilt monday actions and syncs [N2]. Mycel doesn't use syncs.

### 8. Gaps and gotchas

- The **1,000 calls/day cap** on Standard and below (above). The **admin-install requirement** (above).
- **Webhooks are per board.** "Watch everything in the workspace" means a webhook on every relevant board, plus a reconcile job for newly created boards. There's no `create_board` webhook event.
- **No draft state** for updates or notifications. `create_notification` returns no ID, so it can't be checked or retracted.
- `delete_item` is permanent per the docs. Prefer `archive_item` in workflows.
- Guests: Standard bills every 4 guests as 1 seat; Pro and Enterprise allow unlimited guests. Guests see only shareable boards [M15]. **The board's kind (`share`) is the reliable guard signal.**
- Asset `public_url` links let anyone without a login read the file for 1 hour. Never surface them outside Mycel.
- Quarterly breaking changes. `update_form_tag` was removed in 2026-10, for example [M14].

## Asana

### 1. Summary

A task and project tool: tasks (with subtasks, dependencies, assignee, due date and custom fields) in projects (list or board, with sections), comments (called "stories"), attachments, forms, approvals, status updates, goals and portfolios. Small companies use it for team task lists, client delivery, marketing calendars and request intake through Asana Forms. Asana reported 25,928 "Core" customers spending at least $5k a year (see ranking).

Top workflows:

1. **Intake:** an email or Asana Form becomes a task in the right project and section, with an assignee, due date and fields.
2. **Triage:** classify new tasks, set the priority custom field, and route them by moving section or assigning.
3. **Follow-ups:** an overdue or idle task gets a nudge comment for the assignee.
4. **Status digests:** a project's state becomes a status update, or a Gmail draft to a client.
5. **Templated kickoffs:** a new client creates a project from a template.

### 4. Triggers

- **Webhooks** [A4] (updated 2026-03-23); creation and filters [A7] (updated 2026-05-27).
  - Created with `POST /webhooks {resource, target, filters}`.
  - **Handshake:** during creation, Asana POSTs to the target with `X-Hook-Secret`. The target must echo the header back with 200/204 before the create call returns 201. So Mycel's route must answer synchronously, while the create request is still open.
  - **Signature:** `X-Hook-Signature`, an HMAC-SHA256 of the body using the secret.
  - **Heartbeat:** every 8 h. If the target fails for 24 h, the webhook is **deleted**. It is also deleted 72 h after its resource is deleted.
  - **Retries:** exponential backoff for up to 24 h; the target has 10 s to respond.
  - **Delivery:** at-most-once; events can be lost and can't be replayed. "On average within a minute; most within 10 minutes."
  - **Payloads are compact** (resource, action, parent, user per Asana's schema), so Mycel always re-fetches. That fits invariant 8.
  - **Limits:** 1,000 webhooks per resource, 10,000 per token.
  - **Filters:** workspace, team, portfolio and goal webhooks **must** have filters, and they allow only project, portfolio, goal, project-template and membership events. **A workspace-level webhook can't watch tasks.** To watch tasks, Mycel needs **one webhook per project**, plus a workspace webhook on `project added` to catch new projects.
  - On a project or task, events cover tasks (`added`, `changed`, `removed`, `deleted`, `undeleted`), stories (comments: `added`, `changed`, `removed`, `undeleted`), and attachments (only `deleted`, `undeleted`). A new attachment shows as a story. `fields` filters (e.g. only `completed`, `assignee`) are allowed below workspace level.
- **Polling:** `GET /events?resource={task|project|goal}&sync=`. Sync tokens expire after 24 h or sooner (412 returns a fresh token and means re-crawl). Up to 100 events per call, with `has_more`. A project subscription includes its tasks' events [A6]. Also `GET /tasks?project=&modified_since=`.
- **Recommended:** webhooks per project, with an `/events` or `modified_since` sweep as backstop, because delivery is at-most-once.

### 5. Auth

- **OAuth:** authorize at `https://app.asana.com/-/oauth_authorize`, tokens at `/-/oauth_token`. Access tokens last about 3600 s, with long-lived refresh tokens. PKCE (S256) is supported. Revoke at `/-/oauth_revoke`. "The application _must_ be available in the user's workspace" (app distribution settings) [A2] (updated 2025-09-12).
- **Granular scopes** [A1] (updated 2026-09-03): `tasks:read/write/delete`, `projects:read/write/delete`, `stories:read/write`, `attachments:read/write/delete`, `custom_fields:read/write`, `tags:read/write`, `users:read`, `teams:read`, `team_memberships:read`, `workspaces:read`, `workspaces.typeahead:read`, `webhooks:read/write/delete`, `project_templates:read`, `task_templates:read`, `portfolios:*`, `goals:read`, `time_tracking_*`, `ooo_entries:*`, `openid`/`email`/`profile`.
  - They have been in GA since about July 2025 [A11].
  - **Gaps: no scope covers sections, status updates, or the Events API.** Those endpoints answer "One of the following scopes must be present: default", and Asana's advice is to switch the app to **Full permissions** [A12b]. As far as the forum thread shows, an app picks either granular scopes or Full; it can't add `default` alongside them.
  - **So Mycel must choose:**
    - **Full permissions:** simple, broad, works everywhere.
    - **Granular scopes:** least privilege, with no sections (moving tasks between board columns), no status updates and no `/events` polling. Webhooks plus `modified_since` would have to replace `/events`.
- No admin install is required: any user whose workspace allows the app can authorize it, and it acts with that user's permissions. Enterprise admins can restrict apps (admin controls weren't covered in the docs I read).
- No app review for a private OAuth app. Listing in Asana's App Directory has its own process, which I didn't research.

### 6. Limits

Source: [A3] (updated 2026-07-03).

- **Per token:** **150 req/min on Free, 1,500 on paid**, with a separate budget for each token.
- **Concurrent requests:** 50 GET, 15 writes.
- **Cost-based limiter** on graph-heavy requests (no figures given).
- **Search:** 60 req/min.
- **Jobs:** 5 concurrent duplication or instantiation jobs per user.
- 429 responses carry `Retry-After`, and rejected requests still count.
- Per-user OAuth tokens each get their own budget. That suits Mycel's per-member connections.

### 7. Nango

- Provider `asana` (OAuth2), `default_scopes: [default]` (= Full permissions). It retries on `retry-after` and paginates with `next_page.offset` [N1]. To use granular scopes instead, the Nango integration's scopes must be overridden, and the Asana app must be registered with those scopes.
- **No `webhook_routing_script`**, so Mycel handles the `X-Hook-Secret` handshake and HMAC in its own route.
- `asana-mcp` (MCP OAuth2, `https://mcp.asana.com/v2`) and `asana-scim` also exist [N1]. Asana's V2 MCP server is GA, and V1 is being shut down [A14].

### 8. Gaps and gotchas

- **Premium gates:** custom fields [A9] and workspace search [A5] need a paid plan. On Free, a workflow can't read or set "Priority" fields and can't search; it has to list tasks by project.
- **A workspace-level webhook can't watch tasks.** That means per-project webhooks, a webhook on new projects, and heartbeats to answer. The 24-hour failure rule deletes a webhook silently, so a reconcile job must re-create missing webhooks.
- **At-most-once delivery:** polling is needed as backstop.
- **Assigning or following by email can pull an outsider in.** An email on a non-company domain becomes a guest [A13]. The adapter must refuse emails outside the org's domain for `internal_reversible` actions.
- **Mentions don't notify** people who aren't followers or the assignee [A12]. A workflow that "pings Sam" must also add Sam as a follower.
- **Deprecations:** `vacation_dates` on workspace memberships was removed around October 2026 (replaced by `/ooo_entries`) [A14b]. Custom types for projects and portfolios become opt-out on 2027-01-13 [A14c].
- No API for Asana Forms (create or edit), Rules, or the Inbox.

## Notion

### 1. Summary

Docs, wiki and lightweight databases: pages made of blocks, plus databases, each holding one or more **data sources** (tables) of pages with typed properties. Comments, file uploads, views and AI meeting notes complete it. Small companies use it as a wiki and SOP store, a meeting-notes home, and a database used as a CRM, request log, content calendar or hiring tracker. **For Mycel, Notion is first a source of company knowledge for the builder and for workflows, and second an action target.**

Top workflows:

1. **Request log:** an email or form becomes a page in a data source with set properties (status, owner, due).
2. **Meeting follow-up:** AI meeting notes produce action items, which become pages or tasks, plus a Gmail draft recap.
3. **Knowledge-grounded replies:** a workflow drafting a Gmail reply looks up the relevant SOP or price list in Notion.
4. **Tracker hygiene:** stale rows get a comment for the owner; a status change moves the page or updates related rows.
5. **Weekly summaries:** recently changed pages are summarized into a new summary page.

### 2. Capability table

Notion's API is REST at `https://api.notion.com/v1`, with the `Notion-Version` header (latest: **`2026-03-11`**). There are no OAuth scopes. ### 4. Triggers

- **Webhooks** [O1][O2]:
  - **Subscriptions are created only in the integration's settings UI** (one per integration, not per install). No API creates them. A one-time `verification_token` is POSTed to the endpoint and pasted back into the UI. Each event carries `X-Notion-Signature`, an HMAC-SHA256 of the body keyed with that token.
  - **Events:**
    - Pages: `page.created`, `page.content_updated`, `page.properties_updated`, `page.moved`, `page.deleted`, `page.undeleted`, `page.locked`, `page.unlocked`, plus a page transcript-deleted event.
    - Databases: `database.created`, `.moved`, `.deleted`, `.undeleted`. `database.content_updated` and `database.schema_updated` are deprecated from 2025-09-03.
    - Data sources: `data_source.created`, `.content_updated`, `.schema_updated`, `.moved`, `.deleted`, `.undeleted`.
    - Comments: `comment.created`, `.updated`, `.deleted` (need the read-comments capability).
    - File uploads: `file_upload.created`, `.completed`, `.expired`, `.failed`.
    - Views: `view.created`, `.updated`, `.deleted`.
  - **Payload:** IDs and metadata only: `entity` {id, type}, `authors`, `workspace_id`, `integration_id`, `subscription_id`, `accessible_by` (public connections), and `data` (`parent`, `updated_blocks`, `updated_properties`). **No content**, which fits invariant 8.
  - **Latency:** most within a minute, all within 5 min. Aggregated events (most `page.*`, `data_source.*`) are batched. Non-aggregated ones (comments, locks) arrive in seconds.
  - **Retries:** up to 8 attempts with exponential backoff over about 24 h. Delivery is **at-most-once**.
  - **Routing:** use `workspace_id` plus `accessible_by` to map an event to Mycel connection(s). Several members of one workspace may each have installed the app.
  - A Notion Form submission creates a page in a data source, so it arrives as `page.created`.
- **Polling:**
  - `POST /v1/search` sorted by `last_edited_time` desc, which covers everything shared with the connection.
  - `POST /v1/data_sources/{id}/query` with a `last_edited_time` filter.
  - Neither has a delta token, and timestamps are minute-granular in practice (not verified here).

### 5. Auth

- **Public integration (OAuth):** authorize at `https://api.notion.com/v1/oauth/authorize?owner=user`, tokens at `/v1/oauth/token`. The response has `access_token`, `refresh_token`, `bot_id`, `workspace_id` and an optional `duplicated_template_id`. **Token refresh exists** (Refresh, Introspect and Revoke token endpoints) [O5][O12]. Expiry isn't stated in the docs.
- **The page picker defines scope.** During OAuth the user picks the pages and databases to share (children are included). "Only that user can interact with the connection," and each member must authorize separately [O5][O13]. That maps cleanly onto Mycel's per-member connection with `owner_scope: member`. But **the builder only sees what each member chose to share**, so org-wide knowledge needs promotion, or a member who shares the wiki root.
- **Capabilities, not scopes:** set once on the integration (read, update or insert content; read or insert comments; user info with or without email). The same set applies to every install, so a read-only Mycel would need a separate integration.
- **Installation scope** ("any workspace" vs "selected workspaces only") is fixed at creation and can't be changed. Only "any workspace" can list on the Marketplace [O13].
- **No admin install** is needed by default. Admin controls on Enterprise weren't covered in the pages read. Marketplace listing has a separate process, which I didn't research.
- **Free multi-member workspaces have a 1,000 lifetime block limit.** After a 3-day grace period, block-creating writes fail with 403 `restricted_resource` and `block_limit: block_creation` [O14].

### 6. Limits

Source: [O4]; changelog [O3].

- **Per connection, over a 60 s window: 180 req/min (average 3/s) on Free, Plus and other plans; 600 req/min (10/s) on Business and Enterprise.** Enforced since 2026-09-09.
- **Per workspace:** a limit shared by every connection, scaled by plan. Added 2026-06-16. Its `Retry-After` can exceed a minute, so another integration can starve Mycel.
- **Query data source:** about 3 req/s per connection, a separate limit.
- 429 responses carry the `rate_limited` code and `Retry-After`.
- **Payload sizes:** 1,000 blocks and 500 KB per request; 100 elements per block array; rich text 2,000 chars per text object; 100 relations or people per request.
- **Files:** single-part ≤ 20 MB; per file 5 MiB on Free, 5 GiB on paid.
- With these limits, a nightly re-index of a large wiki takes minutes to hours. Index incrementally from webhooks.

### 7. Nango

- Provider `notion` (OAuth2, `owner=user`) has a **`webhook_routing_script: notionWebhookRouting`** and `webhook_user_defined_secret: true`. Nango can receive Notion webhooks and forward them, and Mycel pastes the verification secret into Nango. It also has `token_response_metadata: [workspace_id]` and retries on `retry-after` [N1].
- **Gotcha: the provider's proxy pins the header `notion-version: 2022-06-28`** [N1]. On that version, any database with more than one data source fails for page creation, queries and relation writes [O9b]. **Mycel must send `Notion-Version: 2026-03-11` (or `2025-09-03`) on every proxy call**, and must check that a per-request header overrides the provider default.
- `notion-mcp` (MCP OAuth2 with dynamic registration, `https://mcp.notion.com/mcp`) and `notion-scim` also exist. Nango lists 40+ prebuilt Notion actions [N3].
- **Notion MCP** is worth noting for knowledge. Its `notion-search` does keyword search over **content**, not only titles, plus user lookup. `notion-ai-search` adds connected sources but needs Business/Enterprise with Notion AI. MCP acts with the user's full Notion permissions rather than a page-picker subset [O15]. That is broader than the REST connection and conflicts with least privilege and member scoping. Treat it as an option for the builder's context, not the default.

### 8. Gaps and gotchas

- **The data-source model (2025-09-03).** A database is now a container of one or more data sources:
  - Create pages with `parent.data_source_id`.
  - Query with `/v1/data_sources/{id}/query`.
  - Search filters on `"data_source"`.
  - Webhooks carry new `data_source.*` events.
  - Older API versions break once a user adds a second source to a database [O9b].

  Then 2026-03-11 renamed `archived` to `in_trash`, replaced `after` with `position`, and renamed `transcription` blocks to `meeting_notes` [O9]. **Target 2026-03-11 from day one.**

- **REST search covers titles only.** Using Notion as knowledge means crawling the shared pages, deriving embeddings and facts with `source_ref` = page or block ID + `last_edited_time`, and re-fetching content as markdown at run time (invariant 8). Webhook `page.content_updated` and `page.deleted` events drive re-indexing and the deletion invariant (3).
- **No API to see or change sharing** (guests, public web pages). The guard in "Points that apply to all three apps" can't be checked directly for Notion. Fallbacks:
  - **Allow-list target parents.** The admin marks which Notion areas are internal.
  - Treat any write outside them as `external_send` through the staging pending form.
- **Comments:** they can't be anchored to a text range [O7], resolved comments aren't listed, and editing comments in MCP needs Business+ [O15].
- **Webhook subscriptions are set by hand in the UI**, one per integration. That's fine for one public integration, but it means no programmatic setup per environment.
- **Free workspace block limit** (above). Notion Agents, AI search and meeting notes need Business/Enterprise with Notion AI.
