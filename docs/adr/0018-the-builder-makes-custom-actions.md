# The builder chat makes custom actions when no catalog action fits

Replaces invariant 5's "use existing catalog actions; integration code is written by our team" and `docs/intent.md` non-goal 4. Admins should be able to automate work in any app we've registered, not only the apps our team has built actions for. So when no catalog action fits, the builder chat writes a **custom action**: a description of one call to the app (which address, where each input goes, which results come back), with no code. Mycel's own runtime makes the call through Nango, and a fixed rule, not a model, sets its risk level from the call itself (invariant 4). When one call can't do the job, the builder drafts code instead and sends it to our team, replacing the capability request; the code reaches workflows only after we review it into the shared catalog. We chose request descriptions over letting the builder deploy code, because no signal a fixed rule can trust gives arbitrary code a risk level, and none of the products we studied lets an AI create a lasting action whose risk it sets itself (`docs/research/integrations/builder-made-integrations.md`).

## Consequences

- **Risk:** a read is `read`. Every other call is at least `external_send`, so it waits for a person each time it runs, because no rule can tell a record change from words sent in someone's name (ADR-0019). The rule refuses deletes, refunds, voids and any write in an accounting or payments app. To run without a review, an action goes through our review into the catalog.
- **Approval:** a new custom action appears in the builder's proposal, saying in plain words what it calls and how risky the rule made it, and the admin accepts it with the proposal.
- **Ownership:** a custom action belongs to the company that made it. Accepted custom actions don't change; an edit makes a new one, and switching a published workflow to it is a new workflow version under M5's rules. Prebuilt workflows, when we make them, use only the shared catalog.
- **Try it** runs a custom read for real and shows the exact request a custom write would send, without sending it.
- **Apps:** the builder works only in apps our team has registered with the vendor, starting with `docs/research/integrations/ranking.md`'s order; asking for any other app comes to us. Letting admins connect a vendor's MCP server by its address alone, where the vendor allows apps to register themselves, is to revisit once those servers leave preview and their terms allow apps like ours.
- **When:** its own milestone after M11, taking over M10's capability requests.
