# Workflow builders: how they design workflow creation

Checked 2026-10-20 against primary sources: each product's help centre, docs, changelog, and n8n's source on GitHub. Each claim links to the page it comes from. Dates are given where a feature is new or still changing.

Two of the products have closed or are closing, and two have changed shape:

- **Relay.app shut down in September 2026** and deleted all accounts ([relay.app](https://www.relay.app/)). Its docs are cited from Internet Archive snapshots of docs.relay.app taken on 2026-08-18.
- **Pipedream Workflows shuts down on 2027-03-31** and is in maintenance mode. Pipedream is keeping only Connect, its integration API ([notice](https://pipedream.com/docs/workflows)).
- **Lindy** and **Gumloop** docs no longer describe a step-by-step flow editor. Both are now agents with triggers ([Lindy routines](https://docs.lindy.ai/teammate/routines), [Gumloop](https://docs.gumloop.com/index)), so they appear only where they still document something relevant.

## 1. The visual editor

- **Zapier** shows a Zap "like a flow diagram". Clicking a step opens a right sidebar with **Setup**, **Configure** and **Test** tabs, and paths can be collapsed ([editor](https://help.zapier.com/hc/en-us/articles/16722578092429)). Testing a trigger pulls sample data from the app. Testing an action really creates the record. Results appear under "Data out" and can be mapped into later steps. The trigger and every Filter and Paths step must pass a test before you can publish ([test steps](https://help.zapier.com/hc/en-us/articles/18811411817741)).
- **Make** starts a scenario with "the giant plus in the center of the canvas". You add modules with the **+** at the end of a route ([first app](https://help.make.com/step-3-add-your-first-app), [another module](https://help.make.com/step-3-set-up-another-module)). A filter sits on the line between two modules ([filtering](https://help.make.com/filtering)). After **Run once**, each module shows an "operation bubble" that opens its output ([test](https://help.make.com/step-5-test-your-scenario)). Route order is set in an "Order routes" dialog, with optional "Auto-align" ([router](https://help.make.com/router)).
- **n8n** stores an `[x, y]` position on every node ([`INode` source](https://github.com/n8n-io/n8n/blob/master/packages/workflow/src/interfaces.ts)). **Tidy up** (1.82.0, 2025-03-03) "instantly aligns nodes … untangles connections" ([release notes](https://docs.n8n.io/changelog/release-notes-1.x)). Test data can be pinned or mocked ([pin data](https://docs.n8n.io/build/work-with-data/pin-and-mock-data)). **Position changes behaviour:** branches run "from topmost to bottommost … the leftmost branch executes first" ([execution order](https://docs.n8n.io/build/flow-logic/understand-execution-order)).
- **Power Automate**'s new designer is a "vertical top-to-bottom card layout", where "the **+** button appears between actions". Microsoft admits it "can struggle visually with deeply nested structures … past depth 3" and opens complex flows with every branch collapsed ([designers](https://learn.microsoft.com/en-us/power-automate/classic-vs-modern-designer), updated 2026-05).

## 2. Branching

- **Zapier Paths** run "one at a time, left to right", and every path whose rules hold runs. Zapier advises making rules exclusive to stop "the same Zap run from triggering actions in more than one branch". **Fallback** runs "if no other path branch's rules are met". The alternative, **Always run**, can't be combined with Fallback. Limits: 10 paths per group and 3 nested Paths steps. Paths is not on the Free plan ([Paths](https://help.zapier.com/hc/en-us/articles/8496288555917), updated 2026-07-01; [logic](https://help.zapier.com/hc/en-us/articles/34372501750285)).
- **Make** has two tools. The Router "runs all conditions in the set order" and its routes "can't be merged back together". **If-else** (page created 2026-02-13) runs "only the first condition that evaluates as `true`", then **Else**, and a **Merge** module can rejoin its routes ([If-else and Merge](https://help.make.com/if-else-and-merge)). A Router's fallback route takes data "that doesn't fit the condition of all other routes" ([router](https://help.make.com/router)).
- **n8n**: **If** has a true output and a false output. **Switch** has an option, **Send data to all matching outputs**. It is off by default, which sends an item only "to the first output matching the conditions". An item that matches nothing goes to the fallback: **None** ("Ignore the item. This is the default"), an **Extra Output**, or **Output 0** ([Switch](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.switch)).
- **Power Automate**: a condition has **If yes** and **If no** sides ([condition](https://learn.microsoft.com/en-us/power-automate/add-condition)). Cloud flows run on the Logic Apps workflow language, which that page links to, and the Logic Apps Switch works like this: "only one case should match", cases are unique constant values, only equality is checked, and otherwise "the default section" runs ([switch](https://learn.microsoft.com/en-us/azure/logic-apps/logic-apps-control-flow-switch-statement)).
- **Pipedream** splits the choice by step type. If/Else and Switch run "the **first** branch that matches", so rule order matters. **Parallel** runs "**all** matching branches". If Else or Default is turned off and nothing matches, the run carries on after the block ([If/Else](https://pipedream.com/docs/workflows/building-workflows/control-flow/ifelse), [Switch](https://pipedream.com/docs/workflows/building-workflows/control-flow/switch), [Parallel](https://pipedream.com/docs/workflows/building-workflows/control-flow/parallel)).
- **Relay.app**: "only one path within a group will be taken", checked left to right. "Path B is set to be activated for cases where no other Path is matching." Paths could nest and were reordered by right-clicking ([archived Paths](https://web.archive.org/web/20260818020027/https://docs.relay.app/flow-control/paths)).

## 3. Conditions

- **Zapier** has text operators (contains, exactly matches, is in, starts with, ends with, and their negatives), number (greater than, less than), date (after, before, equals), boolean (true, false), and exists / does not exist for any type ([rules](https://help.zapier.com/hc/en-us/articles/8496180919949)). Rules in a group are combined with AND, and **Add Or rule group** adds an alternative group. That is one level: any of several all-of groups ([filters](https://help.zapier.com/hc/en-us/articles/8496276332557)).
- **n8n** has typed operators for string (including regex), number, date, boolean, array (contains, length) and object. Every type has exists and is empty. A node joins all its conditions with one **AND** or one **OR** ([If](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.if)). The docs describe no nested groups.
- **Make** lists exists / not exists plus text, number, date and array operators ([filtering](https://help.make.com/filtering)).

All of them test the trigger's data and earlier steps' outputs. None lets a flow condition be written in plain language. Lindy's "Smart Filter", which "narrows event triggers in plain English", is the only example found ([routines](https://docs.lindy.ai/teammate/routines)).

## 4. Running paths together, and joins

- **Zapier classic**: "You cannot add shared actions after all path branches". The fix is to "duplicate them in each branch or use a Sub-Zap". A slow step in one path holds up the paths after it ([Paths](https://help.zapier.com/hc/en-us/articles/8496288555917)). **Next Gen Zaps** (early access) add branches that "split and rejoin" ([Next Gen Zaps](https://help.zapier.com/hc/en-us/articles/48391476448141)).
- **Make**: before If-else and Merge, a help page listed workarounds because "there is no converger module" ([converger](https://help.make.com/converger)).
- **n8n Merge** has Append, Combine (by matching fields, by position, or every combination), SQL Query and Choose Branch modes. Combine and Choose Branch "always wait until the data from both inputs is available". Since 1.49.0, Merge takes more than two inputs ([Merge](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.merge)). Branches run one after another, not at the same time ([execution order](https://docs.n8n.io/build/flow-logic/understand-execution-order)).
- **Power Automate / Logic Apps**: the **+** between steps offers "Add a parallel branch". These branches run at the same time. A join step's **Run after** lists the last step of each branch, and it waits for all of them ([branches](https://learn.microsoft.com/en-us/azure/logic-apps/logic-apps-control-flow-branches)).
- **Relay.app**: steps after a path group run whichever path was taken. Data made inside the paths is usable afterwards only if "_every_ path in a group has a step that creates, updates, or fetches an object of the same type" ([archived Paths](https://web.archive.org/web/20260818020027/https://docs.relay.app/flow-control/paths)).

## 6. AI and plain-language builders

- **Zapier Copilot** (Beta) sits in the editor's left sidebar ([Copilot](https://help.zapier.com/hc/en-us/articles/23503999825421)). **Auto-build** makes changes itself. **Ask as you build** "suggests changes but asks for your confirmation before making them". Checkpoints let you revert, and "Show reasoning" explains its choices ([best practices](https://help.zapier.com/hc/en-us/articles/45327353705997), updated 2026-05-29). In **Next Gen Zaps**, "the agent then drafts the change", which the user can see in visual or **TypeScript** form, kept apart from the live version ([Workflow Manager](https://help.zapier.com/hc/en-us/articles/49005047515021), updated 2026-10-19).
- **Make Maia** (public beta, announced 2026-03-31) is a chat "on the left side of the Scenario Builder". It "shows you her work as she builds on the canvas", and you undo with **Revert to this version** on a version listed in the chat ([intro](https://help.make.com/introduction-to-maia-by-make), [launch](https://help.make.com/meet-maia-your-ai-and-automation-co-worker)). Make warns that "multi-page prompts" make Maia skip steps ([best practices](https://help.make.com/maia-by-make-best-practices)).
- **n8n Assistant** (2.29.9, 2026-07-09, Preview) replaced the AI Workflow Builder, which "generated a workflow and handed off". The Assistant "runs what it builds, detects failures, and retries". It opens "side-by-side … with the workflow canvas", and publishing waits for your approval ([changelog](https://docs.n8n.io/changelog/readme), [docs](https://docs.n8n.io/build/ways-of-building-workflows/n8n-assistant)). Version history's **Compare changes** (2.13, 2026-03-16) shows two versions "side by side with changed nodes highlighted".
- **Power Automate Copilot** first suggests a trigger and actions. You refine it or click **Keep it and continue**, then check connections, and only then does the designer open ([create](https://learn.microsoft.com/en-us/power-automate/create-cloud-flow-using-copilot), updated 2026-09). Microsoft advises "one request per message" ([tips](https://learn.microsoft.com/en-us/power-automate/copilot-cloud-flows-tips)).
- **Lindy** fills in "the name, trigger, and schedule" from a description. A routine has no steps: just a trigger, a prompt and a destination ([routines](https://docs.lindy.ai/teammate/routines)).
- **Gumloop** and **Lindy** gate actions per app, not per step. Gumloop's settings include **Ask for writes/deletes**, and each connector's tools are "sorted into read-only and write" when it is added ([Gumloop](https://docs.gumloop.com/core-concepts/human_in_the_loop)). In Lindy, "reads are never guarded" ([Lindy](https://docs.lindy.ai/integrations/overview)).

**Not found:** no product documents a per-change diff in the chat for the user to accept or reject.

## 7. Integrations

- **What they lead with.** Zapier's directory opens with Google Sheets, Gmail, Slack, Google Calendar and Google Drive, out of 10,330+ apps ([apps](https://zapier.com/apps)). n8n's opens with Google Sheets, AI Agent, HTTP Request and Gmail, out of 2,367 ([integrations](https://n8n.io/integrations/)). Make's directory leads with Salesforce and ServiceNow, out of 3,500+ ([integrations](https://www.make.com/en/integrations)), but its first tutorial uses Google Sheets "Watch New Rows" ([tutorial](https://help.make.com/step-3-add-your-first-app)). These counts come from marketing pages.
- **How integrations are modelled.** All of them split work into triggers and actions. Make adds **searches**, and triggers are either **polling** ("Watch …", run on the schedule) or **instant** (webhooks) ([module types](https://help.make.com/types-of-modules)). In Zapier, the polling/instant split is fixed per app. Users sign in once per app account to create a **connection**, for example by OAuth in Make ([connection](https://help.make.com/step-4-create-a-connection)). Lindy has **personal** and **team** connections, and "every action for that tool turns on at once" ([Lindy](https://docs.lindy.ai/integrations/overview)).

## What this means for Mycel

1. **The planned layout follows the vertical designers.** Zapier and Power Automate's new designer both use automatic top-to-bottom layout, "+" between steps, and a side panel for the selected step. Make and n8n chose free placement and later added Auto-align and Tidy up. In n8n, where a branch sits on the canvas even decides when it runs. Not allowing dragging avoids both problems. Power Automate's trouble past three levels of nesting suggests capping nesting and letting paths collapse, as Zapier does.
2. **The first-match / every-match setting has a direct precedent.** n8n Switch has exactly this setting, and it defaults to first-match. Make (If-else vs Router) and Pipedream (If/Else vs Parallel) offer the same choice as two step types. Zapier's every-match Paths come with advice to make rules exclusive. Default to first-match and name both options in plain words. Show the order paths are checked in, left to right on the graph. Since paths can't be dragged, give the side panel "move left / right" controls.
3. **The otherwise path is standard.** Every product has one. Under every-match, Zapier and Make run it only when no other path ran, and Mycel should use the same rule. "Stops the run unless it has steps" matches n8n's default fallback, "Ignore the item".
4. **No joins is the older choice.** Zapier classic Zaps and Make's Router have no joins. Make (February 2026) and Zapier Next Gen Zaps added them, and n8n, Power Automate, Pipedream and Relay already had them. The cost of no joins is that a shared final step, such as labelling the message, has to be copied into every path. That's acceptable for v1, but the spec should leave room for "continue after the branch". Relay's rule is a good model for the data side: an output is usable after the branch only if every path produces one of the same kind.
5. **One level of all-of / any-of is enough.** Zapier goes one level deep, and n8n allows a single AND or OR. Give classify answers "is / is one of". Give extracted values typed operators (text, number, date). Give every condition type "is empty / exists".
6. **There are working models for the later features.** For "wait then check", Relay's "Wait for reply" and "Wait for object to match rule". For failure paths, Zapier's per-step Success/Error split. For "ask a person", Zapier's and Relay's approval timeouts with a choice to continue or end the run. For for-each, decide early whether each item is its own run (Zapier) or results are gathered again (Make's Aggregator).
7. **Proposals would go further than any competitor.** All four large products put chat beside the graph. The confirm-first designs (Zapier's "Ask as you build", Power Automate's "Keep it and continue") support making the admin accept each Proposal, and no competitor shows a per-change diff. Highlighting changed steps on the graph, as n8n's version compare does, would be a cheap way to show one. Microsoft and Make both say long requests go wrong, so the builder should propose small changes.
8. **Approval settings and generated code are where Mycel differs on purpose.** Gumloop's "Ask for writes/deletes" is close to catalog risk levels, but there the user sets it per app. In Mycel only the catalog decides (Invariant 4). Zapier Next Gen Zaps generate TypeScript. Mycel's builder outputs specs, never code (Invariant 5).
9. **Leading with Gmail and Sheets matches the market.** Zapier and n8n list Google Sheets and Gmail first. Treating polling vs instant triggers as fixed per app, as Zapier does, fits the Nango connector design.
